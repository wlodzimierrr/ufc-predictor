# Phase 5 history identity policy v1

This policy is confined to the fourteen event/participant groups in the pinned
Phase 5A v2 capture. It does not change Phase 3B guards, warehouse rows, the
166 frozen exclusions, the feature recipe, or the original exclusive cutoff
2026-10-02. Source rows are immutable; normalization creates a separate view.

An event and participant match, a precautionary exclusion, a URL preference,
or an outcome agreement alone never establishes duplicate identity. Each group
must be classified as proven duplicate, proven distinct occurrences, or
unresolved. Unresolved groups remain in the derived view and block *all*
history indexing and preparation readiness. They cannot be quarantined to
produce a usable subset.

For the manual July/August announcements, affirmative duplicate evidence must
include the preserved manual-card construction code and its unique ACTIVE_BOUTS
entry, exact deterministic manual UUID and URL construction from the captured
participant IDs, and one corresponding occurrence on the preserved official
event card identified by fighter profile links and fight detail link. Names are
used only to validate the manual URL construction; source profile links and
UUIDs establish participant identity. Both records must have compatible
non-provenance fields and statistics. These checks establish that the manual
entry represents the same intended announcement, not a second bout. Keep the
official occurrence's entire source row, because it supplies the occurrence
link corroborated by the event card. Do not blend fields or statistics. All
original source rows and their orientation remain in the lineage ledger.

For other stale upcoming versus completed source URLs, a single current card
entry is insufficient to rule out cancellation/replacement or another
occurrence. Require an explicit source ID transition, redirect or preserved
announcement revision mapping the old URL to the completed occurrence. Absent
that evidence, retain both rows and block readiness, even when only one enters
resolved history. No result is inferred or ingested from supplementary pages.

The narrow same-event occurrence contract permits the 1997-12-21
Sakuraba–Silveira pair only after the event card corroborates two distinct
detail links and participant profile IDs, and the captured rows and separate
participant statistics support two occurrences. Occurrence keys are the real
source detail links; retain the original event ID and each bout ID. The
contract asserts no within-date sequence. Both bouts use strictly earlier-date
histories and date-frozen challenger Elo. Both enter later histories once.
This does not permit any other repeated pair without reviewed evidence.

Normalize identities before constructing fighter, opponent, statistic or Elo
indexes. A proven duplicate maps every alias to the retained original source
bout ID. Compare statistics by fighter ID, independently of bout orientation;
reject conflicts instead of choosing a preferred statistic. Preserve sparse
statistics without inventing zeroes. Do not synthesize fight or event IDs.

Expand exclusions over the entire proven alias equivalence class before any
fitting, preprocessing, OOF or calibration membership is returned. An excluded
alias makes its canonical occurrence ineligible for all those operations.
Independently captured excluded results may enter strictly earlier histories
once, as allowed by the preregistration. The legacy reference bootstrap remains
the exact separately accepted population, with no challenger feature repairs.

Every decision records source row hashes, evidence path/hash and identity
projection, occurrence keys, orientations, chosen whole-row/statistic lineage,
and conflicts or exact missing evidence. The normalizer revalidates these
contracts. Publication is exclusive, checksummed and blocked when any group is
unresolved. A future ready preparation additionally requires independent
deterministic rebuilds, complete lineage and guarded loading; it is never
authorized to fit a learner merely by this policy.
